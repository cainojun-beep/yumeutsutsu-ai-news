## 1. AWS Quickがチーム向けワークフロー強化とマルチエージェント対応を発表

**出典：** [AWS Machine Learningの記事を読む](https://aws.amazon.com/blogs/machine-learning/new-in-aws-quick-more-capable-flows-an-updated-web-experience-and-agents-that-work-together/)

**要旨：** AWSはチーム向けAIワークスペース「AWS Quick」のアップデートを発表しました。チャットで業務プロセスを記述するとエージェントやツール、構造化データを組み合わせた“Flow”を自動構築でき、決定論的ステップや長時間・大容量データ対応でワークフローの再現性を高めます。Webアプリのホーム画面に日次ブリーフを表示してタスクを継続実行できるようにし、複数専門エージェントが並行して作業し結果を統合するマルチエージェントオーケストレーションや、Meta AdsやAmplitudeなどの外部データ接続も可能になりました。日本語を含む複数言語対応やセキュリティ・ガバナンス設定の強化も盛り込まれており、チーム運用や業務標準化の効率化に直結する内容です。

### ポイント

- チャットからフローを自動生成し可視化できる。  
- マルチエージェントで並列処理し単一応答に統合。  
- 外部データソース接続と多言語対応（日本語含む）。

### 注意点

- 詳細な運用上の権限管理やデータ連携設定は導入企業側で検討が必要。  
- 新機能の実運用での安定性やコスト影響は個別検証が必要。

## 2. 自社ホストLLMの遅延とコストを削減する分散KVキャッシュエージェントスキルを公開

**出典：** [AWS Machine Learningの記事を読む](https://aws.amazon.com/blogs/machine-learning/cut-self-hosted-llm-cost-and-latency-with-the-distributed-kv-caching-agent-skill/)

**要旨：** AWSは自己ホスト型LLMの推論コストと初動遅延を抑えるため、Amazon ElastiCacheを用いた分散KVキャッシュの導入手順と評価を支援するAgent Skillを発表しました。会話履歴など長いコンテキストの再計算（prefill）を省くことでTTFTを最大80％、コストを最大40％削減するベンチマークを示しています。エージェントは事前適合性チェック、KVTraceによるワークロード試算、vLLM等への接続設定まで案内し、導入前に効果検証が可能です。特に長い会話履歴や頻繁なプロンプト再利用がある法務やドキュメントQA等で効果が見込めます。

### ポイント

- 分散KVキャッシュでGPU再計算を削減しTTFTとコストを改善。  
- KVTraceで自社ワークロードを無料で試算可能。  
- Agent Skillで設定・診断・トラブル対応を対話的に支援。

### 注意点

- 効果はプロンプト長や再利用頻度などワークロード特性に強く依存する。  
- キャッシュ導入に伴う運用コストと整合設定ミスのリスクを評価する必要がある。

## 3. Amazon Textract Insightsを一般提供、文書向けの検証可能な生成AI機能を追加

**出典：** [AWS Machine Learningの記事を読む](https://aws.amazon.com/blogs/machine-learning/announcing-amazon-textract-insights-verifiable-generative-ai-for-documents/)

**要旨：** AWSはAmazon Textractの新機能「Textract Insights」をGAとして公開しました。自然言語で抽出したいフィールドを定義するブループリント（JSON Schema）を使い、最大3,000ページの混在ドキュメントを分割・分類してフィールド抽出、各値に信頼度スコアとページ単位の出典根拠を返します。従来のOCR＋カスタムパイプラインを一本化し、W-2や給与明細など公開ブループリントや独自ブループリントで運用可能です。金融・保険・医療などで自動化の受け入れ判断を容易にする設計で、信頼性とトレーサビリティを重視する業務に適しています。

### ポイント

- 単一APIで混在ドキュメントの分割、分類、抽出を実行。  
- 各抽出値に信頼度とページ根拠を返すため自動化閾値の設定がしやすい。  
- 公開ブループリントで一般的な書類に即利用可能。

### 注意点

- 複雑な業務要件や稀な書式ではカスタムブループリントやレビュー設計が必要。  
- 抽出精度やスコアの閾値設定はドメインごとに検証が要る。

## 4. SageMaker HyperPodのGlobal Inference Gatewayを公開、リージョン/クラスタ横断ルーティングを実現

**出典：** [AWS Machine Learningの記事を読む](https://aws.amazon.com/blogs/machine-learning/introducing-amazon-sagemaker-hyperpod-global-inference-gateway-one-endpoint-across-regions-and-clusters/)

**要旨：** AWSはSageMaker HyperPodの二層目としてGlobal Inference Gatewayを導入しました。複数クラスタや複数リージョンに分散したGPU容量を一つのSageMaker管理エンドポイントでルーティングし、各クラスタのKVキャッシュ利用率やキュー深度などリアルタイム信号を基に最適クラスタへ転送します。これにより負荷集中時の待ち行列を抑え、クラスタ障害時の自動フェイルオーバーを実現します。クライアント側の変更は不要で、SigV4/IAM認証とPrivateLink経由のプライベート接続を維持する点が強調されています。

### ポイント

- 一つの管理エンドポイントで複数クラスタ／リージョンへルーティング。  
- 統計に基づくクラスタ選定でアイドルGPUを活用可能。  
- SigV4/IAMとPrivateLinkでセキュアに通信。

### 注意点

- クロスリージョントラフィックやデータ転送コスト、レイテンシ設計は導入時に検討が必要。  
- 公開・グルーピング設定を誤ると意図しないルーティングが発生する可能性がある。

### 注意点

- OSの設計変更やサードパーティの対応状況により制限効果は限定される可能性がある。
